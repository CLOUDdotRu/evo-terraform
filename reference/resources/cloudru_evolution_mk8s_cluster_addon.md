# cloudru_evolution_mk8s_cluster_addon (Resource)



## Example Usage

```terraform
resource "cloudru_evolution_mk8s_cluster_addon" "resource_cluster_addon" {
  # Поле cluster_id является неизменяемым. При изменении значения ресурс будет пересоздан.
  cluster_id = "00000000-0000-0000-0000-000000000000"
  # Поле name является неизменяемым. При изменении значения ресурс будет пересоздан.
  name        = "evocs"
  app_version = "v0.0.6"
  # Варианты значений параметра resolve_mode:
  # RESOLVE_CONFLICTS_MODE_NONE, RESOLVE_CONFLICTS_MODE_OVERWRITE, RESOLVE_CONFLICTS_MODE_PRESERVE
  resolve_mode = "RESOLVE_CONFLICTS_MODE_OVERWRITE"
  preserve     = true
  # Позволяет переопределить дефолтный таймаут провайдера для определенного метода. Если нужно указать бесконечный таймаут, то нужно указать например 0s, тогда таймаута не будет.
  timeouts {
    create = "60m"
    update = "30m"
    delete = "20m"
  }
  # Игнорировать изменения таймаутов: это предотвращает  лишние обновления ресурса при смене значений таймаутов в конфигурации
  # Но следует учитывать, что метод delete в ресурсе читает значение таймаута из стейта и, если его нужно изменить, то этот блок стоит закомментировать
  lifecycle {
    ignore_changes = [timeouts]
  }
}
```

## Schema

### Required

- `app_version` (String) Версия приложения в формате SemVer.
- `cluster_id` (String) Идентификатор кластера, в котором установлен плагин.
- `name` (String) Машинное имя плагина.
- `resolve_mode` (String) Режим разрешения конфликтов. Возможные значения: * `RESOLVE_CONFLICTS_MODE_NONE` — если пользователь ранее самостоятельно установил плагин в кластере, то существующие манифесты не перезапишутся. Добавление плагина может завершиться неудачно. * `RESOLVE_CONFLICTS_MODE_OVERWRITE` — если пользователь самостоятельно установил плагин в кластере или внес изменения в его конфигурацию, то все пользовательские изменения откатятся до рекомендуемых значений. * `RESOLVE_CONFLICTS_MODE_PRESERVE` — выполнится сохранение пользовательских изменений при обновлении плагина. Для операции добавления плагина значение неприменимо.

### Optional

- `addon_configuration` (String) Пользовательская конфигурация плагина в JSON-формате согласно схеме в виде экранированной строки. Например, `{\"config\": {\"logaas\": {\"logGroupId\": \"a1s8***sd7t\"}}}`. Поддерживает переменные автоподстановки, заключенные в {{ }}: * `{{clusterID}}` — уникальный идентификатор кластера. * `{{clusterName}}` — программное имя кластера. * `{{productInstanceID}}` — идентификатор экземпляра продукта. * `{{nodeCIDR}}` — CIDR сети узлов. * `{{serviceCIDR}}` — CIDR сервисной сети. Если поле не указано, то переиспользуется последняя конфигурация.
- `preserve` (Boolean) Признак сохранения ресурсов плагина в кластере. Если true — все манифесты и связанные ресурсы плагина останутся в кластере, но управление плагином через Managed Kubernetes будет недоступно. Опция подходит в случаях, когда важно сохранить текущее состояние и настройки плагина, но больше не требуется централизованное управление через Managed Kubernetes.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))
